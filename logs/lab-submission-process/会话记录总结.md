这是 Windows 编辑后的 submit.sh 使用了 CRLF 换行，而 Linux bash 需要 LF。
修复方式是：

或者在本地把 submit.sh 强制保存为 LF。
这个问题和 OJ 是否接受提交无关，但会导致虚拟机里 make submit 直接失败。
经验：
Windows + Linux 混用时，shell 脚本必须注意 LF 换行。CRLF 会让 bash 报 $'\r'。

9. 最后一个隐患：submit.zip 不能留着再 make
虽然仓库历史已经清理干净，但还有一个重要细节：
Makefile.git 里自动 commit 的逻辑是：
git add . -A --ignore-errors
git commit ...
也就是说，运行：
make
make compile
make test
make run
时，如果当前目录有未忽略的：
submit.zip
它会被自动 git add 进去，再次污染历史。
所以如果 .gitignore 不忽略 submit.zip，每次运行自动 commit 前都要先删：
rm -f submit.zip
更推荐永久修复 .gitignore：
/submit.zip
/__submit_tmp__/
/submissions_lab*/
这样以后即使 submit.zip 留在目录中，也不会再被自动提交。
经验：
根因修复后，还要堵住复发入口。这里的复发入口就是 Makefile 自动 git add . -A。
