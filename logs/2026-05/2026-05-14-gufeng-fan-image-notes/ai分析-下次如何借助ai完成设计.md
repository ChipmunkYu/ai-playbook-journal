# AI 分析：下次如何更好借助 AI 完成扇面设计

日期：2026-05-14

分析者：AI（openai/gpt-5.5）

分析对象：`logs/2026-05/2026-05-14-gufeng-fan-image-notes/rcd/` 下的会话记录

目的：不是评价本次图像结果好坏，而是从人和 AI 的协作过程里，分析下次如何更有效地借助 AI 完成设计。

---

## 1. 这次协作大致分成几个阶段

从记录看，这次不是单纯“写 prompt 生成图”，而是一个从设计意图到图像迭代的完整过程。

### 1.1 元素与方向探索

对应记录：`rcd-元素讨论和提示词打磨.md`

一开始目标比较抽象：夏天用、清凉、雅致、有生活感、安逸闲适。

AI 在这个阶段比较适合做：

- 发散可用元素；
- 解释不同元素能营造什么气氛；
- 帮用户把“感觉”转成场景方向；
- 给出多个候选构图。

这一阶段用户的角色主要是筛选：例如确定要竹子、不要人，之后又在水、石、茶具、古琴等方向之间切换。

这个阶段的协作效果比较好，因为任务是概念发散和语言组织，不要求 AI 精准控制画面局部。

### 1.2 从方向变成 prompt

对应记录：`rcd-元素讨论和提示词打磨.md`

当用户确定“雨后竹石”“雨后竹荫临水”“竹荫清供”“竹间琴案”等方向后，AI 能把这些方向扩展成完整 prompt。

这一步 AI 的价值主要在：

- 把元素、氛围、构图、色彩、笔触、负面约束分层写清楚；
- 把用户口语化的设计想法改写成图像模型更容易接收的描述；
- 帮用户形成一个可复制、可迁移的设计文本。

不过这里也出现一个问题：有时用户只是要文字，AI 却生成了图片。这说明下次如果只想讨论或总结，需要在开头明确加上“不生成图片，只讨论 / 只输出文字”。

### 1.3 初稿生成与局部迭代

对应记录：`rcd-竹鱼迭代初稿.md`、`rcd-竹鱼迭代迁移雪兔.md`

进入图像生成后，用户开始围绕具体结果做局部修改：竹子角度、竹竿数量、竹叶疏密、水波淡化、鱼的姿态、留白大小、皴擦位置、墨色质感等。

这一阶段开始暴露出 AI 图像生成的主要限制：

- 能理解大方向，但很难稳定执行局部修改；
- 改一个地方时，容易破坏已经满意的部分；
- 对数量、角度、疏密这类结构性要求控制不稳定；
- 对“保持其他不变”的执行能力有限。

也就是说，AI 在“整体概念”和“生成新版本”上比较强，在“像修图软件一样精修局部”上不可靠。

### 1.4 风格迁移与主题迁移

对应记录：`rcd-竹鱼迭代迁移雪兔.md`、`rcd-雪兔简单迭代定稿.md`

后期从竹鱼转向雪兔，用户要求“用类似的风格”画冬天竹子和兔子。AI 能够继承一部分风格语言，例如团扇、水墨、文人画、留白、低饱和、写意等。

但迁移时也会带来新问题：

- 新主体容易回到模型熟悉的写实或插画倾向，例如兔子过于写实；
- 竹子粗细、兔子意象化程度等仍需要继续调；
- 最后比较有效的方式是把满意方向重新总结成一套完整 prompt，再在新会话里做简单迭代。

这说明“迁移”不能只说“类似风格”，最好把可迁移的风格规则抽出来，再单独写新主体的约束。

## 2. 这次人和 AI 的分工特点

### 2.1 用户更适合掌握审美判断和最终取舍

记录里真正推动方向变化的，通常是用户的判断：

- 不要人；
- 不要水，只保留竹子、茶具、桌案；
- 古琴放在矮木桌上，桌后怪石可作凳；
- 竹子太粗；
- 兔子过于写实；
- 水波减少减淡；
- 竹子和鱼之间留白太大；
- 竹叶不要太均匀。

这些判断不是 AI 能自动替用户决定的。AI 可以提供方案，但用户需要负责审美方向、接受或拒绝、局部满意度判断。

### 2.2 AI 更适合做语言化、补全和重组

AI 在以下任务上作用明显：

- 把“夏天看着凉快”拆成雨后、水汽、竹荫、留白、淡墨等视觉语言；
- 把一个元素组合扩写成完整场景；
- 把用户的零散要求整理成系统 prompt；
- 把满意结果反向总结成可复用提示词。

所以 AI 更像“设计助理 + prompt 整理者”，而不是完全可靠的“局部修图执行者”。

### 2.3 AI 不适合承担全部精修责任

记录中反复出现“保持不变”“只改这里”“数量、角度、疏密不要变”等要求。

这类要求更接近图像编辑软件里的图层、蒙版、局部控制，而不是自然语言生成最擅长的范围。

下次如果已经进入很细的局部要求，应该提前判断：继续用 prompt 迭代是否还划算。

## 3. 有效的协作模式

### 3.1 先讨论，不急着生成图

“先不生成图片，只与我讨论设计”是一个有效开头。

它让 AI 先参与设计分析，而不是直接给出随机图。这样用户可以先确定：

- 元素；
- 氛围；
- 场景；
- 构图；
- 反向约束。

这一步适合放在任何正式生成之前。

### 3.2 用户先做方向选择，再让 AI 写 prompt

比如从多个方向中选“雨后竹石”“雨后竹荫临水”“竹荫清供”“竹间琴案”。

这种流程比直接让 AI 给最终 prompt 更好，因为用户能先筛掉不想要的元素，减少后续 prompt 内部冲突。

### 3.3 把 prompt 分层写

比较有效的 prompt 通常包含：

- 画面形式；
- 整体气氛；
- 主要元素；
- 构图要求；
- 色彩；
- 笔触；
- 不要什么；
- 风格关键词。

这种结构方便后续修改，也方便把某一层替换掉，例如从“水鱼”换成“雪兔”。

### 3.4 满意后及时总结

在竹鱼和雪兔会话中，用户多次要求总结提示词、总结画面要求、描述鱼的弯曲形状、描述配色。

这是有效动作，因为图像生成过程容易漂移。及时总结可以把某次满意结果转成文字资产，方便迁移到新会话或新主题。

### 3.5 复杂结构可以先做低细节草稿

“先不管竹叶等等，先用最简单的粗细线条描绘出竹子数量、粗细”这个思路值得保留。

它把问题拆成：

1. 先定竹竿数量、粗细、位置；
2. 再加竹叶；
3. 再加颜色和质感。

虽然后续上质感时仍然可能漂移，但这种分阶段思路比一次性要求模型同时解决结构、笔触、色彩、局部疏密更清楚。

## 4. 反复出现的失败模式

### 4.1 “其他都不变”不可靠

多条记录都出现了类似要求：

- 鱼、水波、已有竹子保持不变；
- 其余都一点不变；
- 现有竹竿、鱼、水、皴擦痕迹不变；
- 保持竹子竹叶形态不变，只去掉勾线感。

这类要求在自然语言里很明确，但对生成模型来说并不等于锁定图层。模型经常会重新生成整张图，导致旧问题回流。

结论：如果某部分已经满意，不应长期依赖“其他不变”来保护它。更适合用参考图、选区、蒙版或外部编辑工具。

### 4.2 竹叶容易从自然错落变成均匀装饰

用户多次强调：

- 竹叶簇不要都一样；
- 数量、形状、浓淡要有区别；
- 分布要有疏密变化；
- 不要太均匀。

这说明竹叶是高风险元素。AI 很容易把竹叶理解成装饰性重复纹样，而不是国画里自然、有疏密、有笔势的竹叶。

下次如果竹叶很重要，应该更早把它单独列为控制对象，不要只在后期补救。

### 4.3 竹竿数量、角度、交叉关系难控制

竹竿相关修改非常多：增加一两杆、不要集中交汇、不要太平行、轻微交叉、左移、变细、不要根部、不要集中于一点。

这些要求本质上是几何结构控制。纯 prompt 可以表达意图，但不擅长稳定执行精确数量和位置。

下次如果竹竿结构重要，可以先让 AI 生成或描述“结构草图”，但最终可能仍需要手动草图、参考图或局部控制工具。

### 4.4 风格和结构经常不能同时保住

记录里出现过：结构改善后，上色质感不理想；颜色合适后，又要求笔触更像水墨写意；去掉勾线感时，又要保持竹子竹叶形态不变。

这说明模型容易在以下目标之间互相牵扯：

- 结构；
- 线条；
- 墨色；
- 质感；
- 局部分布。

下次可以把它看成一个取舍问题，而不是每一步都要求全部保留。

### 4.5 “类似风格”不足以迁移复杂审美

从竹鱼迁移到雪兔时，AI 能继承团扇和水墨氛围，但兔子仍可能过于写实，竹子仍可能太粗。

说明“类似风格”太泛。迁移时最好明确拆出：

- 可继承：宣纸底色、低饱和墨色、留白、写意笔触、文人小品气质；
- 需重写：主体动作、动物抽象程度、季节氛围、竹子粗细、雪的表现方式。

## 5. 对两种路线的判断

### 5.1 详细 prompt 路线

优点：

- 能稳定表达审美目标；
- 适合收敛方向；
- 方便总结和迁移；
- 适合控制不要出现的现代感、写实感、装饰感。

局限：

- prompt 越长，不等于局部越可控；
- 容易把很多要求堆在一起，模型只能大致满足；
- 对数量、角度、局部位置的控制仍然弱。

适合阶段：方向确定后生成初稿，或把满意结果总结成可复用版本。

### 5.2 高自由度路线

对应记录：`rcd-ai高自由度设计.md`

优点：

- 成本低；
- 容易得到意外构图；
- 适合探索 AI 自己会如何组合元素；
- 有时比过度约束的 prompt 更有松弛感。

局限：

- 结果不可控；
- 不适合后期精修；
- 如果用户已有明确局部要求，会很快进入反复修改。

适合阶段：最早期找灵感，或在卡住时重新发散。

## 6. 下次更适合的协作流程

### 6.1 第一阶段：只讨论设计，不生成图

建议开头明确：

```text
先不生成图片，只讨论设计。请给我 3-5 个方向，每个方向说明元素、构图、气氛和可能风险。
```

这个阶段目标不是得到 prompt，而是确定方向。

### 6.2 第二阶段：让 AI 输出多个构图草案

不要急着写完整长 prompt，可以先让 AI 用文字描述构图：

```text
基于我选的方向，给 3 个团扇构图方案。每个只描述主体位置、留白、前中后景关系，不写完整 prompt。
```

这样可以先解决设计关系，而不是马上进入画面细节。

### 6.3 第三阶段：选定一个构图后再写 prompt

prompt 可以分成固定模块：

- 核心目标；
- 构图；
- 元素；
- 风格；
- 色彩；
- 笔触；
- 负面约束；
- 不可妥协项。

其中“不可妥协项”不要太多，最好只保留 3-5 个。

### 6.4 第四阶段：先生成初稿，不急着局部精修

初稿阶段只判断大问题：

- 方向对不对；
- 气氛对不对；
- 构图是否可用；
- 主体关系是否成立。

不要一开始就纠结某一簇竹叶或某一条皴擦。

### 6.5 第五阶段：把修改分成“可 prompt 改”和“需工具改”

每次想改时，先判断属于哪类：

适合 prompt 的修改：

- 整体更淡 / 更浓；
- 更写意 / 更少细节；
- 主体更偏左 / 留白更多；
- 去掉某类元素；
- 气氛更清冷 / 更闲适。

不太适合纯 prompt 的修改：

- 某一杆竹子变细 1/4；
- 某一片竹叶去掉但其他不变；
- 某几处皴擦保留或移动；
- 精确控制竹竿数量和角度；
- 保留 A 的质感，同时替换 B 的结构。

如果进入第二类，应该考虑选区、蒙版、参考图或外部工具。

### 6.6 第六阶段：满意版本立刻做“设计资产化”

每得到一个满意版本，立刻让 AI 输出：

- 一句核心描述；
- 短 prompt；
- 长 prompt；
- 可迁移风格规则；
- 不要项；
- 哪些地方不适合只靠 prompt 复现。

这样下次不是从零开始，而是有一组可复用设计资产。

## 7. 下次可以直接使用的协作模板

### 7.1 设计讨论模板

```text
先不生成图片，只讨论设计。
我想做一个中国古画团扇 / 腰扇扇面，目标气质是：____。
已确定元素：____。
不想要：____。
请给我 5 个方向，每个方向包括：主要元素、构图方式、气氛、优点、风险。
不要写完整 prompt。
```

### 7.2 构图方案模板

```text
我选择方向：____。
请只给构图方案，不生成图片。
给 3 个团扇构图，每个说明：
1. 主体位置
2. 留白位置
3. 前景 / 中景 / 后景关系
4. 视觉重心
5. 可能失控的地方
```

### 7.3 prompt 生成模板

```text
基于方案 __，生成一套图像 prompt。
请按以下结构写：
1. 画面形式
2. 整体气氛
3. 构图
4. 主要元素
5. 色彩
6. 笔触
7. 不要项
8. 最重要的 3 个不可妥协项
```

### 7.4 迭代判断模板

```text
先不要改图。请判断下面修改需求哪些适合用 prompt，哪些更适合用选区 / 蒙版 / 外部工具，并说明原因：
____
```

### 7.5 满意版本总结模板

```text
不要生成图片。请把当前满意版本总结成设计资产：
1. 一句话描述
2. 短 prompt
3. 长 prompt
4. 可迁移的风格规则
5. 容易丢失、需要特别保护的局部效果
6. 不适合只靠 prompt 复现的部分
```

## 8. 简短结论

这次记录显示，AI 最适合参与：前期元素发散、构图语言化、prompt 整理、满意结果总结和风格迁移文本化。

AI 最不稳定的是：后期局部精修、精确数量位置控制、保持旧局部不变、复现某一张图里的特定笔触和质感。

所以下次更好的协作方式不是单纯写更长 prompt，而是把流程分开：

```text
讨论设计 → 选方向 → 定构图 → 写 prompt → 生成初稿 → 分类迭代 → 必要时转工具 → 总结设计资产
```

其中最重要的判断是：什么时候还在做“设计”，什么时候已经进入“图像局部编辑”。前者适合 AI 对话，后者可能更适合选区、蒙版或专业工具。
