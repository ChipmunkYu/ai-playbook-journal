# PPT 展示方法论：从 AI 初稿到导师定稿的经验沉淀

> 分析者：AI（opencode-go/deepseek-v4-flash）
> 分析日期：2026-05-29

---

## 一、核心原则：成果优先

中期答辩（以及大多数科研汇报）的听众最关心的是：

> **你做了什么？做得怎么样？**

而不是：

> **你打算做什么？你的研究背景是什么？**

### 具体做法

1. **把"研究内容"合并到"阶段性成果"中**——不要单独成章，因为研究内容本身就是成果的一部分
2. **减少章节过渡页**——每页都应该是内容页，过渡页的信息密度太低
3. **把"选题背景"改为"研究背景动机"**——强调"为什么做"而非"选了什么题"
4. **目录控制在 3 项以内**——4 项及以上会让听众失去焦点

### 检查清单
- [ ] 听众能否在前 2 页就知道"你做了什么"？
- [ ] 是否有可以合并或删除的章节？
- [ ] 过渡页是否超过了总页数的 15%？

## 二、叙事结构：因果链 > 线性罗列

### 不好的叙事（V1 的问题）
```
背景 → 内容 → 成果 → 计划
```
这是线性罗列，听众被动接收信息，难以形成记忆点。

### 好的叙事（V2 的做法）
```
问题 → 方案 → 验证
```
这是因果链，每页都围绕"为什么做 → 怎么做 → 证明了什么"展开。

### 具体做法

1. **每页都要有"问题"**——没有问题的页面就是信息堆砌
2. **"方案"要对应"问题"**——不要展示与问题无关的方案
3. **"验证"要可量化**——用数据、图表、对比来证明方案有效

### 页面级叙事模板

```
[问题] 现有方法存在什么缺陷？
[方案] 我们设计了什么新方法？
[验证] 实验证明了什么？（附图表）
```

## 三、文字表达：具体 > 抽象

### 对比

| 抽象（V1） | 具体（V2） | 效果 |
|-----------|-----------|------|
| "公平性测试是判断 AI 系统是否可信的重要环节" | "模型从训练语料中习得社会中固有的歧视与偏见" | 从概括变为机制解释 |
| "当前用来判断偏见的公平性测试方法本身是否可靠？" | "指标'语义偏差超阈比例'能否忠实反映偏见？真阳性比例有多少？" | 从抽象追问变为可验证问题 |
| "非敏感变化对照组" | "对性别有关位置做同性变化" | 从概念变为操作 |

### 原则

- **能用动词不用名词**："对性别有关位置做同性变化" > "非敏感变化对照组"
- **能用具体数字不用模糊表述**："真阳性比例有多少？" > "方法是否可靠？"
- **能用因果句不用并列句**："模型从训练语料习得偏见" > "翻译系统可能产生不一致结果"

### 检查清单
- [ ] 每句话是否都在传递具体信息？
- [ ] 是否有可以删除的概括性表述？
- [ ] 关键概念是否可以用操作来描述？

## 四、视觉布局：对比 > 罗列

### 不好的布局（V1）
```
[左侧导航] [标题]
            [进展 1]
            [进展 2]
            [进展 3]
            [进展 4]
```
这是罗列，听众需要自己找出逻辑关系。

### 好的布局（V2）
```
[左侧导航] [标题]
            [问题] vs [方案]
            [旧方法] | [新方法] | [验证]
```
这是对比，逻辑关系一目了然。

### 具体做法

1. **能用对比不用单栏**——左右对比、上下对比、新旧对比
2. **能用三栏不用两栏**——"旧方法 | 新方法 | 验证"比"问题 | 方案"更有说服力
3. **表格 + 图表配合使用**——表格说明"是什么"，图表证明"怎么样"
4. **减少装饰性元素**——背景图、图标等装饰元素不要喧宾夺主

### 常见对比模式

| 模式 | 适用场景 | 示例 |
|------|---------|------|
| 左右对比 | 问题 vs 方案 | 现有方法问题 vs 针对性改进工作 |
| 三栏对比 | 旧方法 vs 新方法 vs 验证 | 原实验 vs 新设计 vs 部分检验证明 |
| 上下分层 | 概念 → 指标 → 流程 | 歧视评估依据 → 指标 → 流程 |
| 表格扩展 | 从 2 行到 4 行 | Nc/Sc 扩展到 Nc/Sc/Nu/S |

## 五、图表使用：真实 > 装饰

### 原则

1. **每张图都要有信息量**——装饰性背景图尽量减少
2. **用真实数据图表替代占位符**——AI 生成的"这里放图"必须替换
3. **图表要配合文字说明**——图不能独立存在，需要文字解释"这张图说明了什么"
4. **图片格式选择**：.png 用于截图和图表，.jpeg 用于照片，避免使用 .wdp 等非标准格式

### 检查清单
- [ ] 每张图是否都有明确的传达目的？
- [ ] 是否有可以删除的装饰性图片？
- [ ] 图表旁边是否有解释性文字？
- [ ] 是否有"这里放图"之类的占位符未替换？

## 六、颜色使用：区分 > 装饰

### 建议方案

| 用途 | 颜色 | 说明 |
|------|------|------|
| 标题/强调 | 红色 | 用于最重要的信息 |
| 问题/质疑 | 黄色/橙色 | 用于需要关注的问题 |
| 正文 | 黑色/深灰 | 常规内容 |
| 导航/标签 | 黑色 | 辅助信息 |

### 原则

- **每种颜色要有明确的语义**——不要为了好看而用颜色
- **颜色种类不超过 3 种**——太多颜色会分散注意力
- **颜色要与内容匹配**——红色用于"重要"，黄色用于"问题"，不要反过来

## 七、AI 辅助 PPT 制作的注意事项

### AI 能做的

- 生成结构框架和内容草稿
- 提供排版建议和模板
- 检查逻辑连贯性

### AI 不能做的（需要人工介入）

1. **填充真实数据**——AI 生成的"这里放图"必须替换为真实图表
2. **判断内容优先级**——AI 倾向于"什么都放"，导师知道"什么最重要"
3. **调整叙事角度**——AI 倾向于线性罗列，导师知道如何建立因果链
4. **选择对比方式**——AI 倾向于单栏布局，导师知道何时用对比
5. **判断语言风格**——AI 可能混入英文或不合适的表述

### 推荐工作流

```
AI 生成初稿 → 导师审阅 → 人工修改 → AI 辅助检查 → 定稿
```

- AI 负责"生成"和"检查"
- 人负责"判断"和"修改"
- 导师的审阅意见是最关键的输入
